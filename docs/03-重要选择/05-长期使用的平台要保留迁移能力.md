# 长期使用的平台要保留迁移能力

一个平台最初只放几份资料，后来逐渐承载作品、客户、收入和日常流程。即使它目前很好用，规则、价格和个人需求也可能变化。提前保留迁移能力，能让未来继续使用更接近主动选择。

## 找出你逐渐交出去的东西

不只看数据文件。用户名、联系人、历史记录、支付渠道、自动化和别人访问你的入口，也可能依赖平台。有些能导出，有些只能部分迁移，还有些属于对方的服务能力，无法复制。

为每个核心用途写一句：“如果它明天不能用，我会失去什么，需要多久恢复？”这有助于区分临时不便与会切断生活或工作的单点依赖。

## 先验证最小的迁移链路

选择一份非敏感、可测试的资料，导出、在另一工具打开，再检查标题、附件、链接和关键格式。文件出现在下载目录，只能证明导出文件存在；实际能否继续使用，需要看后续步骤。

不必频繁把所有工具换一遍。先确认关键成果有你可掌握的副本，重要联系不只存在一个不可替代入口，再根据依赖程度安排复核。维护备份也有成本，应优先保护最难重建的部分。

## 分散不等于到处开户

十个平台各放一份不同版本，可能增加遗失和误用。清楚的主副本、通用格式和恢复方法，常比数量更多更有帮助。真正要降低的是共同受某种变化影响的风险。

例如多个客户都只通过同一平台付款，即使客户彼此不同，也可能一起受到平台规则影响。是否需要替代入口，取决于合同、客户条件和可行成本，不能靠一句“不要依赖任何人”解决。

## 什么时候仍值得深入使用

专用工具可能提供明显收益，与迁移成本一起比较即可。完全避免依赖会失去许多合作和规模带来的便利。目标是知道代价、保住重要选择，并在收益变化时能重新评估。

本篇把交易成本与控制权思想用于数字生活，也借用相关风险的分析视角；没有主张所有平台都不可信。[S08](../../references/sources.md#s08)、[S10](../../references/sources.md#s10)
